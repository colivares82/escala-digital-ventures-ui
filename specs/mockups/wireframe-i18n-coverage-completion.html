i18n coverage completion · reference of translated surfaces

All examples show the same data rendered for a user (or email recipient) whose resolved language is English. Left pane = current production behaviour; right pane = expected behaviour after the fix. Final fallback for every surface is Spanish.

This is not a UI redesign. No layout, component or workflow changes anywhere. The screens, PDFs, Excels and emails shown already exist and work — the only change is that every system-generated label resolves through the existing i18n infrastructure (t() keys, TranslationService, localizedName()) instead of being hardcoded or single-language.

1 · Criterion names — inspection report surfaces (form, detail, PDF, Excel, email)

Physical tests, technical aspects, fabrication defects and natural defects have per-language names defined in the report configurator (nameEs / nameEn / nameIt / nameFr). Every surface that prints a criterion name must resolve it for the consumer's language via the existing localizedName() chain.

2 · Language resolution — who decides the language of each artefact

Single rule across the whole system: the consumer decides. No artefact is tied to the language of whoever created it.

AUI, downloaded PDF, downloaded Excel → language of the logged-in user performing the download (User.preferredLanguage). An admin in Spanish downloading a report of an English client sees it in Spanish; the client downloading the same report from their portal sees it in English.
BEmails (report send, bulk send, cobro send) → resolved recipient language: SendDialog override → Client.preferredLanguage → fallback. Applies to subject, HTML body and the attached PDF — all three in the same language.
CFinal fallback everywhere: Spanish (es). Cline must verify the current fallback of LocaleResolverService (documented as EN) and align it to ES.

Specification summary:
  • No UI redesign: existing screens, exports and emails are reused. Only label resolution changes.
  • One language rule: the consumer decides — downloading user for UI/PDF/Excel, resolved recipient for emails. Final fallback is Spanish on every surface.
  • Criterion names resolve via the existing localizedName() helper on every surface. Snapshot storage of the four name variants must be diagnosed by Cline before implementation; the fix applies to new reports and to reports that are reopened and saved again.
  • Three Excel exports in scope: report Excel, cobro Excel, advanced-search Excel. Labels only — no numeric/date format changes.
  • Cobros: remaining hardcoded UI labels + billing category enum labels translated across UI, PDF, Excel. Free-text descriptions never translated.
  • Master photos: section strings migrated to catalog namespace keys; browser-native file input intentionally left untouched.
  • IT / FR out of scope — deferred to a later iteration after EN is fully verified.
